# rust 开发 uTP  库计划里程碑

---

### V0.1：跑通 Header 序列化与 UDP 收发
**阶段目标**：验证 Rust 位运算与网络字节序，打通最底层的物理通道。

| 维度 | 实现内容 | 侧重程度 |
| :--- | :--- | :--- |
| **核心API** | 极其简陋的函数：`send_udp_packet(header, payload)` 和 `recv_udp_packet()`。 | ⭐ |
| **状态机** | **无**。完全无状态，硬编码字段。 | - |
| **数据结构** | **核心重点**：`UtpHeader` 结构体；实现 `serialize() -> [u8;20]` 和 `deserialize(&[u8])`；处理 `type_ver` 的位运算（高4位Type，低4位Ver）。 | ⭐⭐⭐⭐⭐ |
| **异步驱动** | **无**。使用标准库 `std::net::UdpSocket` 的同步阻塞 `send_to` 和 `recv_from`。 | - |

---

### V0.2：实现状态机与握手
**阶段目标**：让无连接的 UDP 产生“连接”的抽象，协商 Conn ID 和初始序列号。

| 维度 | 实现内容 | 侧重程度 |
| :--- | :--- | :--- |
| **核心API** | 雏形出现：`UtpSocket::bind()`，`UtpSocket::accept()`，`UtpStream::connect(addr)`。 | ⭐⭐ |
| **状态机** | **核心重点**：定义 `UtpState` 枚举；实现三次握手状态流转：`Closed -> SynSent -> Connected`（客户端），`Accepting -> SynReceived -> Connected`（服务端）。 | ⭐⭐⭐⭐⭐ |
| **数据结构** | 引入 `UtpStream` 上下文结构体，保存：`local_conn_id`，`remote_conn_id`，`seq_nr`，`ack_nr`。 | ⭐⭐⭐ |
| **异步驱动** | 引入基础异步：将 `UdpSocket` 换为 `tokio::net::UdpSocket`；`connect` 和 `accept` 返回 `Future`，异步等待握手回应包。 | ⭐⭐ |

---

### V0.3：实现收发缓冲区与大块数据读写
**阶段目标**：突破 MTU 限制，实现滑动窗口的“流式”读写和乱序重组。

| 维度 | 实现内容 | 侧重程度 |
| :--- | :--- | :--- |
| **核心API** | 完善流接口：`UtpStream::send(&[u8])` 和 `UtpStream::recv(&mut [u8])`，支持发送超过 MTU 的大块数据。 | ⭐⭐⭐ |
| **状态机** | 状态基本停留在 `Connected`，逻辑变为**数据驱动**（收到包推进窗口状态）。 | ⭐ |
| **数据结构** | **核心重点**：实现 `SendBuffer`（发送队列，切片并缓存已发未确认包）和 `RecvBuffer`（接收队列，用 `BTreeMap` 暂存乱序包，`VecDeque` 拼装连续数据）。 | ⭐⭐⭐⭐⭐ |
| **异步驱动** | 引入 **多路复用器** 雏形：用一个后台 Task 监听 UDP，根据 `conn_id` 将收到的包通过 `mpsc::channel` 分发给对应的 `UtpStream`；当缓冲区满/空时，通过 `Waker` 挂起或唤醒 `send/recv` 任务。 | ⭐⭐⭐⭐ |

---

### V0.4：实现 ACK 机制与超时重传
**阶段目标**：解决丢包问题，实现可靠性。这是整个协议最难、最复杂的部分。

| 维度 | 实现内容 | 侧重程度 |
| :--- | :--- | :--- |
| **核心API** | API 不变，但 `send()` 变得**可靠**。 | ⭐ |
| **状态机** | 增加超时重传状态逻辑：若 RTO 内未收到 ACK，触发重传。增加优雅关闭逻辑：`Connected -> FinSent -> Destroyed`。 | ⭐⭐⭐ |
| **数据结构** | **核心重点**：在 `SendBuffer` 中为每个包增加 `time_sent` 时间戳；实现 RTT 估算器（计算 `SRTT`、`RTTVar`、`RTO`）。 | ⭐⭐⭐⭐⭐ |
| **异步驱动** | **核心重点**：引入 **定时器轮/ 时间堆**。后台 Task 需要不仅监听 UDP 可读事件，还要监听定时器事件。一旦某个包超时，立刻触发重传逻辑。 | ⭐⭐⭐⭐ |

---

### V0.5：实现 SACK 机制
**阶段目标**：优化重传效率，避免只靠累积 ACK 导致的“滑窗卡死”和“盲目重传”。

| 维度 | 实现内容 | 侧重程度 |
| :--- | :--- | :--- |
| **核心API** | 无变化。 | - |
| **状态机** | 无变化。 | - |
| **数据结构** | **核心重点**：定义 `UtpExtension` 结构体（特别是 SACK 扩展的位图 `BitVec` 或 `Vec<u32>`）；改造 `RecvBuffer`，使其能根据乱序情况生成 SACK 位图；改造 `SendBuffer`，使其能解析 SACK 位图，精准标记哪些包已收到、哪些需要重传。 | ⭐⭐⭐⭐⭐ |
| **异步驱动** | 后台 Task 解析包时，需增加对 `extension == 1` 的分支处理，将 SACK 信息传给重传逻辑。 | ⭐⭐ |

---

### V0.6：实现 LEDBAT 延迟计算与拥塞控制
**阶段目标**：让 uTP 具备“低优先级”特征，在带宽竞争时主动退让，避免挤爆网络。

| 维度 | 实现内容 | 侧重程度 |
| :--- | :--- | :--- |
| **核心API** | API 不变，但 `send()` 的发送速率受 `cwnd` (拥塞窗口) 严格控制。 | ⭐ |
| **状态机** | 引入拥塞状态机（如：慢启动 -> 拥塞避免 -> 超时衰退）。 | ⭐⭐⭐ |
| **数据结构** | **核心重点**：新增 LEDBAT 上下文结构体：`base_delay`（历史最小延迟队列）、`current_delay`（当前延迟采样）、`cwnd`（拥塞窗口字节数）、`in_flight`（在途字节数）。彻底激活 Header 中之前未用到的 `timestamp_microseconds` 和 `timestamp_difference_microseconds`。 | ⭐⭐⭐⭐⭐ |
| **异步驱动** | `send()` 不再仅仅检查缓冲区是否为空，还要检查 `in_flight < cwnd`。如果窗口不足，必须通过 `Waker` 挂起当前发送任务；后台 Task 收到 ACK 计算出新的 `cwnd` 后，再唤醒挂起的发送任务。 | ⭐⭐⭐⭐ |

---

### 总结演进规律

1. **数据结构**：从 `UtpHeader` -> `UtpStream` -> `Buffer` -> `Timer/RTT` -> `SACK BitMap` -> `LEDBAT Context`。数据结构的复杂度逐步递增。
2. **状态机**：V0.2 解决“有没有连接”，V0.4 解决“死没死（断开/超时）”，V0.6 解决“快还是慢（拥塞状态）”。
3. **异步模型**：从 V0.3 开始，Rust 的异步驱动（多路复用 + Waker 通知）是支撑缓冲区读写的基础；到了 V0.4 和 V0.6，定时器和窗口控制更是完全依赖异步事件循环来驱动。
